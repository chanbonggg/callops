# CallOps

갤럭시 통화 녹음을 홈서버에서 안전하게 수집하고, 사용자가 업무 통화로 선택한 녹음만 로컬 AI로 전사·요약하는 개인 자동화 프로젝트입니다.

현재 단계는 **기능 명세 작성 및 승인**입니다. 승인되지 않은 기능은 구현하지 않습니다.

## 확정된 원칙

- 갤럭시 원본은 유지한다.
- 홈서버 삭제가 갤럭시 원본 삭제로 전파되지 않게 한다.
- 모든 녹음은 홈서버에 임시 수신하지만, 업무 통화 선택 전에는 Whisper/Ollama 처리를 금지한다.
- 사적 통화는 홈서버 복사본을 삭제한다.
- AI 처리 승인과 일정·할 일의 외부 등록 승인을 분리한다.
- n8n은 CallOps 전용 인스턴스가 아니라 홈서버의 공용 자동화 허브로 운영한다.
- 실제 비밀값, 녹음, 전사문, DB 데이터와 백업은 Git에 저장하지 않는다.

다음 세 문서를 순서대로 검토합니다. 모두 승인 전 초안이며 설치·연동이 완료되었다는 뜻이 아닙니다.

| 문서 | 내용 |
|---|---|
| [1. 이 프로젝트](docs/01-project.md) | CallOps 전체 기능·코드, P0~P8 개발, C0~C7 앱/DB 배포·동기화·알림 워크플로우·Calendar·운영 |
| [2. 데스크톱](docs/02-desktop.md) | 환경 확인 D0~D6, 로컬 Whisper/Ollama, 워커 통신·권한·재시작·청소 |
| [3. 서버](docs/03-server.md) | 프로젝트와 독립적인 공용 n8n만: S0~S4 설치·시스템 DB·인증·접속·이력·업데이트·복구 |

문서는 실행 장소가 아니라 관리 책임으로 나눕니다. CallOps 앱·DB가 Ubuntu 홈서버에서 실행돼도 개발·배포·운영은 프로젝트 업무입니다. 공용 n8n 자체의 배포 설정은 프로젝트 밖에서 관리하고, 그 안에 넣을 CallOps 워크플로우·외부 계정 연결은 프로젝트에서 관리합니다.

현재 구현 착수 후보는 프로젝트의 수집·분류·DB 큐와 가짜 워커 테스트입니다. 데스크톱 사양·알림 채널·갤럭시 폴더가 확정되지 않아도 이 부분은 개발할 수 있습니다.

기존 [SPEC-01 초기 상세 초안](docs/specs/01-recording-ingestion-classification.md)은 참조용으로 유지합니다. 세 문서에서 보완한 보관·재수신·승인/외부 상태 분리와 구현 범위는 [프로젝트 문서의 변경 사항](docs/01-project.md#1-문서의-적용-범위와-현재-상태)을 함께 검토합니다.
