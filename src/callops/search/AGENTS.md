# 전사 검색 모듈

## 책임과 구현 의도

수락된 전사를 거래처·실제 통화 날짜와 키워드로 조회한다. 검색 모듈은 기존 artifact를 제한된 범위에서 직접 읽는다. [전사 검색 계약](../../../docs/p2-p3-server.md#전사-내용-검색)

## 검색 흐름

- 공통 메뉴의 **전사 검색**은 `/search`를 연다. 상단에서 **키워드 검색**과 **통화에 질문**(`/questions`)을 오간다. `/search`의 POST는 세션과 CSRF를 확인하고, `matching_segments()`는 거래처·한국 날짜 필터, 업무 승인 상태와 최신 STT artifact의 보관 기한을 적용한다.
- 통화 모듈의 무결성 검사를 통과한 구간에 Unicode NFC와 `casefold`를 적용한다. 공백으로 나눈 검색어가 한 구간에 모두 들어 있으면 일치한다.
- 최근 최대 50건과 16MiB를 읽어 최대 5개 결과를 표시한다. 읽기 실패와 범위 제한은 화면에서 알린다. 결과 링크는 통화 ID·전사 artifact ID·구간 ID를 고정한다.

## RAG 근거 검색

- 서버 내부 `retrieve_evidence()`는 키워드 검색과 같은 후보 조회 및 artifact 검증을 사용한다. 연속된 전사 구간을 묶고, 각 구간의 원본 시각과 상세 링크를 반환한다.
- 임베딩 함수를 주입해 DB 잠금 밖에서 코사인 유사도를 계산한다. 최신 전사·업무 승인·삭제·만료 상태를 다시 확인한 결과만 최대 5개 반환한다. 임베딩을 저장하지 않는다.
- `/questions`는 사용자 세션과 POST CSRF가 필요하다. 거래처·기간은 선택 필터다. 현재는 어휘 규칙으로 검색해 발화를 직접 인용하고, 여러 미팅 후보나 취소·변경 단서가 있으면 확인을 요청한다.
- BGE-M3 임베딩과 Qwen 답변의 데스크톱 실행 계약이 있다. 서버는 pull 작업 할당과 pgvector 검색을 연결하고, 모델에 보낸 요청의 ID를 전사 버전·구간에 매핑해 권한·삭제·만료를 표시 직전에 재확인해야 한다. [워커 실행 계약](../../../ai-worker/README.md#질문-모델-워커-실행)
- 질문 결과의 인용 재생 링크는 통화 모듈과 같은 원음 만료 판정을 따른다. 유효한 전사는 텍스트 근거로 계속 제공한다.

## 변경 시 확인

- 사적·만료 자료를 차단하고 각 근거가 해당 통화의 artifact인지 검증한다. 검색어는 폼 입력으로 처리하고, 근거 문자열은 Jinja에서 이스케이프한다. 조회로 파일과 상태를 변경하지 않는다.
- 검색 구조를 바꿀 때도 원래 날짜 필터와 근거 URL을 보존한다. 경계는 P3에서 검증하고, 튜닝은 개발 세트로만 한다. 최종 세트는 설정을 고정한 뒤 평가에 사용한다. [전사·검색 테스트](../../../tests/p3/test_transcript_views.py) · [개발 평가 자료](../../../tests/fixtures/rag-development.json) · [최종 평가 자료](../../../tests/fixtures/rag-final.json)
