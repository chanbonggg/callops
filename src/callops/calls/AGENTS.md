# 통화 모듈

## 책임과 구현 의도

녹음 수신, 분류, 통화 정보, 원음·전사 상세와 관리 사본 정리를 맡는다. PostgreSQL의 통화 상태와 파일의 실제 존재를 함께 확인한다. `Service.transaction()`의 공용 advisory lock은 한 서버에서 처리·검색·삭제가 같은 파일을 동시에 변경하지 않도록 한다. [통화 서비스](service.py)

## 요청과 파일 흐름

- 통화 목록의 **할 일 목록** 링크는 직접 입력 할 일 화면으로 이동한다. 통화 ID를 전달하지 않으며 할 일의 조회·변경은 할 일 모듈이 담당한다. [할 일 화면](../../../docs/p2-p3-server.md#직접-입력-할-일-화면)

- `ingest`는 완료 체크섬을 받은 파일을 임시 격리 파일로 복사하고, 복사 전후 파일 상태와 내용·음성 형식을 검증한다. [오디오 검증](audio.py)은 PCM WAV, AAC·ALAC M4A, MP3, AMR-NB·WB를 허용한다. SHA-256으로 동일 콘텐츠를 찾고 수신 경로는 `receipts`에 기록한다. 전송 중인 `.part`는 수신 도구가 관리한다.
- 미분류·보류 상태에서 상대와 실제 통화 시각을 수정한다. 입력은 한국 시간, DB는 UTC로 다룬다. 업무 승인과 STT 작업 생성은 한 트랜잭션으로 처리한다.
- 상세와 검색의 전사 읽기는 `read_transcript_artifact()`를 공유한다. 호출자가 통화·artifact의 관계와 권한을 확인하고 트랜잭션을 유지한다. 읽기 함수는 보관 기한·크기·해시·스키마를 검사한다.
- 상세의 합성 요약은 표시 중인 전사를 입력으로 사용한 성공 분석 결과에서 읽는다. 요약 근거는 같은 전사의 구간 링크를 사용하고 분석 파일이 유실·손상·만료되면 전사만 표시한다.
- 원음은 세션·보관 기한·삭제 상태·해시를 검사한 뒤 반환한다. M4A·AMR의 PCM 호환 재생은 업무 승인 상태에서만 제공하며 디스크에 사본을 남기지 않는다.
- 인용 구간 재생은 원본 전사 artifact와 구간 ID로 조회하며, 검증된 시작·끝의 샘플만 WAV로 제공한다. 구간 생성 뒤 업무 승인·삭제·원음 기한을 다시 확인한다.
- `request_delete()`는 조회·처리를 즉시 차단하고 일정 후보를 지운다. `maintain()`은 inbox·격리·파생 파일을 복사본별로 정리하고 워커 확인까지 추적한다. 같은 이름에 새 데이터가 있으면 보호하며, 새 수신이 검증되면 이전 수신 기록의 경로를 정리된 것으로 처리한다.

## 변경 시 확인

- 경로는 `safe_path()`로 검증한다. 폰 원본과 임의 경로를 삭제 범위에 넣지 않는다. 파일 이름 재사용, 작업 취소, 일부 사본 삭제 실패를 회귀 검사에 포함한다.
- 30일 원음·90일 전사 조회 제한과 사적 삭제 경로가 있다. 보관 만료 후 전체 파일 정리와 브라우저 `Range` 재생은 별도 작업이다. [서버 구현 계약](../../../docs/p2-p3-server.md)
- 수신·분류·메타데이터는 P2, 전사 수명주기는 P3에서 검증한다. [수집](../../../tests/p2/test_ingestion.py) · [통화 정보](../../../tests/p2/test_recording_metadata.py) · [전사 조회](../../../tests/p3/test_transcript_views.py)
