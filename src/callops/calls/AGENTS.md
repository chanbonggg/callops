# 통화 모듈

## 책임과 구현 의도

녹음 수신, 분류, 통화 정보, 원음·전사 상세와 관리 사본 정리를 맡는다. PostgreSQL의 통화 상태와 파일의 실제 존재를 함께 확인한다. `Service.transaction()`의 공용 advisory lock은 한 서버에서 처리·검색·삭제가 같은 파일을 동시에 변경하지 않도록 한다. [통화 서비스](service.py)

## 요청과 파일 흐름

- 목록은 필터·상태·상세 링크를 제공한다. 통화 정보 저장, 재생, 분류는 상세에서 제공하고, 업무 지정이나 정보 저장 성공 후 같은 상세로 돌아온다. 목록과 상세는 [공통 레이아웃](../schedule/templates/layout.html)을 사용한다.

- `ingest`는 완료 체크섬을 받은 파일을 임시 격리 파일로 복사하고, 복사 전후 파일 상태와 내용·음성 형식을 검증한다. [오디오 검증](audio.py)은 PCM WAV, AAC·ALAC M4A, MP3, AMR-NB·WB를 허용한다. SHA-256으로 동일 콘텐츠를 찾고 수신 경로는 `receipts`에 기록한다. 전송 중인 `.part`는 수신 도구가 관리한다.
- 미분류·보류 상태에서 상대와 실제 통화 시각을 수정한다. 입력은 한국 시간, DB는 UTC로 다룬다. 업무 승인과 STT 작업 생성은 한 트랜잭션으로 처리한다.
- 상세와 검색의 전사 읽기는 `read_transcript_artifact()`를 공유한다. 호출자가 통화·artifact의 관계와 권한을 확인하고 트랜잭션을 유지한다. 전사가 유실·손상·만료되면 통화 상세는 전사 내용을 빼고 표시하며, 버전 고정 링크와 인용 재생은 오류로 차단한다.
- 상세의 합성 요약은 표시 중인 전사를 입력으로 사용한 성공 분석 결과에서 읽는다. 요약 근거는 같은 전사의 구간 링크를 사용하고 분석 파일이 유실·손상·만료되면 전사만 표시한다.
- 원음은 세션·보관 기한·삭제 상태·해시를 검사한 뒤 반환한다. M4A·AMR의 PCM 호환 재생은 업무 승인 상태에서만 제공하며 디스크에 사본을 남기지 않는다.
- 인용 구간 재생은 원본 전사 artifact와 구간 ID로 조회하며, 검증된 시작·끝의 샘플만 WAV로 제공한다. 구간 생성 뒤 업무 승인·삭제·원음과 전사의 기한을 다시 확인한다.
- 업무 통화 상세에서 [할 일 후보 검토](../../../docs/p2-p3-server.md#통화에서-나온-할-일-후보-검토)를 연다. 승인과 현재 할 일 생성은 한 트랜잭션에서 처리한다.
- `request_delete()`는 조회·처리를 즉시 차단하고 일정·할 일 후보와 연결된 현재 내용을 정리한다. 모의 Calendar의 로컬 일정 본문도 지우고 이벤트 ID와 전송 해시를 보존한다. `maintain()`에서 할 일 후보가 만료돼도 승인된 현재 할 일은 유지한다. 전체 삭제에서 inbox·격리·파생 파일을 복사본별로 정리하고 워커 확인까지 추적한다. 같은 이름에 새 데이터가 있으면 보호하며, 새 수신이 검증되면 이전 수신 기록의 경로를 정리된 것으로 처리한다.
- `maintain()`은 원음과 각 산출물의 삭제 상태를 먼저 커밋한 뒤 서버 파일을 정리한다. 원음 만료는 STT, 산출물 만료는 그것을 입력으로 쓰는 분석과 해당 산출물의 관련 워커 사본을 대상으로 한다. 서버 삭제 실패 또는 워커 미확인이 있으면 다음 청소를 기다린다. `recover()`는 기한이 지난 파일의 부재를 새 장애로 기록하지 않는다.

## 변경 시 확인

- 경로는 `safe_path()`로 검증한다. 폰 원본과 임의 경로를 삭제 범위에 넣지 않는다. 파일 이름 재사용, 작업 취소, 일부 사본 삭제 실패를 회귀 검사에 포함한다.
- 조회와 STT는 같은 `audio_expired()` 판정을 쓰고, 중복 수신은 최초 원음 기한을 유지한다. 30일 원음·90일 산출물 청소와 재수신·재시작·워커 미확인을 [만료 통합 테스트](../../../tests/p3/test_retention.py)에서 확인한다. 브라우저 `Range` 재생은 별도 작업이다. [서버 구현 계약](../../../docs/p2-p3-server.md#업무-데이터-만료와-파일-정리)
- 수신·분류·메타데이터는 P2, 전사 수명주기는 P3에서 검증한다. [수집](../../../tests/p2/test_ingestion.py) · [통화 정보](../../../tests/p2/test_recording_metadata.py) · [전사 조회](../../../tests/p3/test_transcript_views.py)
