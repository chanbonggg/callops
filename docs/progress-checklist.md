## 일반 개발환경 작업 순서

합성 데이터·로컬 HTTPS·임시 PostgreSQL·가짜 워커로 진행한다. 이 순서는 GPU가 없는 현재 환경의 작업 제안이며 웹 MVP의 단계별 통과 기준은 그대로 적용한다.

Ubuntu와 임시 PostgreSQL에서 P3 회귀와 로컬 D5를 검증했다. 다음 배포 검증은 합성 녹음의 수신·분류·삭제와 홈서버의 VPN 워커 연결을 대상으로 한다. CallOps의 알림 대기열과 재시도는 로컬 가짜 전송으로 검증할 수 있다.

### 1. 통화 목록·상세·전사 검색 UI 반영

**UI 반영(2026-11-17)** — [승인된 Figma 시안](https://www.figma.com/design/FTB08BRgu0d4mXnIWlg8MP?node-id=24-931)을 기준으로 목록·상세·전사 검색에 공통 모바일 배치를 적용했다. 통화 정보 저장과 분류를 상세에 모았고, 하단 전사 검색은 `/search`를 열며 상단에서 `/questions`로 이동한다. 원본 재생을 시작한 뒤에는 브라우저의 재생·일시정지·탐색 컨트롤을 사용한다. 버전이 고정된 근거 화면은 해당 구간을 강조하고 같은 버전의 다른 구간도 확인할 수 있다.

### 2. 로컬 브라우저에서 조작 흐름 확인

- [x] 로컬 HTTPS의 Chrome 1090px·390px·320px에서 로그인, 목록 필터, 업무 상세, 요약·검색 결과의 고정 근거, 2초 합성 WAV의 원본·인용 재생, 검색 일치·빈 결과와 통화 질문 왕복을 확인했다. 320px에서 긴 거래처명이 줄바꿈되고 입력칸이 화면 밖으로 넘치지 않으며 스크롤로 주요 버튼을 누를 수 있음을 확인했다. 1090px에서 통화 정보 저장 → 업무 지정 → 전사 없음 안내까지 조작했다.
- [x] Chrome 390px·1090px에서 직접 일정을 등록·수정·삭제하고, 시작보다 이른 종료를 제출했을 때 제목·시작·종료 입력이 보존되는 것을 확인했다. 두 탭에서 먼저 저장한 뒤 이전 폼의 저장이 충돌 안내로 거부됐다.
- [x] 공통 메뉴 변경 후 Chrome 390px·1090px에서 통화 목록 → 할 일, 통화 목록 → 전사 검색 → 통화 질문 이동을 확인했다. 직접 입력 할 일의 등록·기한 변경과 해제·완료·삭제, 중복 등록과 이전 탭 저장 차단을 확인했다. 통화 질문에서 필터 패널을 열고 가상 거래처 미팅 질문을 제출해 답변과 고정 전사 근거, WAV 응답을 확인했다.
- [x] 일정 후보 검토 화면에 공통 헤더·하단 메뉴와 후보 카드를 반영했다. 후보의 저장된 값을 확인하고 **수정**에서 편집한 뒤 별도로 승인한다.
- 완료 기준은 **화면 배치**와 **조작 결과**를 각각 확인하고 기록하는 것이다. 갤럭시 실기기와 실제 Whisper 구간 대조는 기기 준비 후 수행한다.
