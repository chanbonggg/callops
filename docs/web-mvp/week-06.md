# 6주차 · Calendar 양방향과 사용자 과제

[이전 주](week-05.md) · [전체 계획](README.md) · [다음 주](week-07.md)

**종료 목표** · 승인된 일정 한 건을 Google Calendar로 보내고, Google에서 바꾼 내용을 웹으로 가져온다. 사용자가 합의 확인부터 일정 변경 확인까지 직접 수행한다.

## 작업

- [ ] 승인된 시험 계정과 전용 Google Calendar 한 개를 사용한다. 전송 항목은 일정 제목·시작·종료 등 등록에 필요한 최소 정보로 한정한다. 원음과 전체 전사는 CallOps에 보관한다.
- [ ] CallOps에서 승인한 일정의 생성, 웹에서 확인한 일정 수정·삭제의 외부 반영을 시험한다. 응답이 유실된 생성은 기존 이벤트를 확인한 뒤 재시도한다.
- [ ] Google에서 연결 일정의 변경분을 가져와 현재 일정을 갱신한다. Google 삭제는 웹에 삭제 상태로 표시하고 자동 재생성을 막는다. 동시 수정은 충돌로 표시해 사용자가 선택할 수 있게 한다.
- [ ] 일정 상세에 **통화 당시 합의와 현재 일정**을 구분한다. 원래 전사 근거는 유지한다. 시제품의 역방향 동기화 완료 기준은 CallOps와 연결된 일정의 수정·삭제 반영이다.
- [ ] 갤럭시 테스트 폴더에서 새 녹음 전송부터 업무 지정·AI 처리·근거 답변까지 통합 시험한다. 전송 중단·서버 재시작·사적 분류 후 원본 보존도 확인한다.
- [ ] 사용자 과제를 진행한다. ① 과거 합의의 근거 찾기 ② 후보를 수정해 등록하기 ③ Google에서 변경한 일정 확인하기. 기존 방식과 비슷한 난이도의 과제로 완료 여부, 시간, 잘못 선택하거나 수정한 횟수, 막힌 화면을 기록한다.

## 통과 기준

| 시험 | 기대 결과 |
| --- | --- |
| 승인 → Google 생성 → 동일 요청 재시도 | 연결된 이벤트는 한 건이다. |
| Google에서 오후 2시를 오후 3시로 수정 | 웹은 현재 오후 3시를 표시하고 통화의 오후 2시 근거를 보존한다. |
| 웹·Google 양쪽의 수정 및 삭제 | 각 방향의 반영 결과를 기록한다. 동시 수정은 확인이 필요하고 삭제된 일정을 자동 재생성하지 않는다. |
| 만료 인증 또는 일시 장애 | 동기화 실패·재연결 상태를 보여주고 사용자 승인 상태는 보존한다. |
| 사용자 과제 | 실제 사용자 1인의 결과는 사례 평가로 기록한다. 추가 참여자가 있으면 같은 과제를 별도 기록한다. |
