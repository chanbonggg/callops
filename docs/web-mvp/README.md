## 개발 범위

실제 사용자의 업무는 **거래처 영업 및 일정 생성**이다. 상담·방문 약속, 자료 전달 기한, 후속 연락 시점과 일정 정정·취소를 대표 사례로 사용한다. 통화 당시 합의와 현재 일정은 각각의 출처를 확인해 표시한다.

| 우선순위 | 이번에 만들 것 | 최종 시연 |
| --- | --- | --- |
| 필수 | 갤럭시 신규 녹음 자동 전송, 업무 지정, 로컬 전사·요약, 통화 RAG와 근거 구간 재생 | 녹음 1건이 웹에 들어오고, 사용자 질문에서 답변의 근거 원음을 열 수 있다. |
| 선택 · 이번 구현 목표 | 일정·할 일 후보 확인·수정·승인, 웹에서 직접 입력·관리, Google Calendar 1개와 연결 일정 양방향 동기화 | 후보 승인 후 일정 1건을 등록한다. Google에서 시간을 바꾸면 웹이 현재 일정과 당시 합의를 구분해 표시한다. |
| 후속 | Flutter 앱, 이메일 연동 | 이번 시제품은 PC·모바일 브라우저에서 사용한다. |

업무 지정과 일정 등록 승인은 별개다. 미분류·사적 통화는 AI 호출 0회, 사적 통화 삭제는 관리 사본에만 적용한다. 테스트 기본 경로는 합성 데이터·임시 PostgreSQL·모의 외부 어댑터다. 실제 기기·홈서버·GPU 환경 변경·OAuth는 연결 범위를 확인한 뒤 진행한다. [하네스와 승인 범위](../harness.md)

## 웹 앱의 기능 모듈

웹 앱은 Starlette로 구성하고 Uvicorn에서 한 배포 단위로 실행한다. `auth`는 사용자·워커 인증, `calls`는 수집·분류·목록·상세, `processing`은 작업 큐와 결과 검증, `search`는 전사 검색과 근거 링크를 맡는다. 일정 후보 검토와 관리, Calendar 연동은 기능을 구현할 때 모듈을 추가한다. 데스크톱 AI 워커는 기존 서버 API로 연결한다. [저장소 구성](../01-project.md#3-소유권과-저장소-구성)

## 데스크톱 준비 전 진행 순서

2026-11-11에 사용자가 GPU 데스크톱 없이 진행 가능한 작업부터 하도록 요청했다. 주차 문서의 순서는 의존 관계를 기준으로 앞당겨 진행한다.

1. 통화 상대·시각 저장 및 날짜 검색과 개발용 전사 10건·질문 20개 준비를 완료했다.
2. 합성 전사의 저장·조회와 거래처·기간별 키워드 검색을 구현했다. 결과에 고정된 구간 출처를 표시한다. 의미 검색·실제 모델 결과 수락은 별도로 시험한다.
3. 웹 후보 검토·일정·할 일 관리와 모의 Calendar 연동을 구현한다.
4. 최종 평가용 10건·20문항을 준비하고 삭제·권한·취소·재시도 회귀를 진행한다.

Whisper·Qwen·BGE-M3의 실제 실행·품질·속도 측정과 GPU 워커 연동은 데스크톱 준비 후 검증한다. 현재 개발용 Python에는 `av`·`ollama` 패키지가 없어 실제 디코딩·모델 실행을 전제로 완료 표시하지 않는다.

## 같이 작업할 때

1. 이번 주 문서에서 가장 앞의 미완료 작업을 고른다. 작업 전에 `git status --short`와 관련 코드·명세를 확인한다.
2. 체크박스는 **완료 기준을 확인한 뒤** 체크한다. 결과 표에 날짜, 실행한 명령 또는 시연 절차, 실제 결과, 남은 경계를 기록한다.
3. 기존 하네스와 PostgreSQL 검사를 재사용한다. 새 기능은 해당 주차에서 정의한 실제 코드 경로와 실패 사례를 별도로 시험한다.
4. 운영 장비나 외부 계정 시험이 막히면 합성 데이터로 검증 가능한 작업을 계속한다. 모의 시험과 실제 연동 결과는 구분해서 기록한다.

```text
python scripts/check.py
python scripts/test_postgres.py --pg-bin E:/PostgreSQL/bin --phase P3
python -m unittest discover -s ai-worker/tests -v
```

두 번째 명령은 별도 임시 PostgreSQL 클러스터에서 P1~P3를 실행한다. 마지막 명령은 전사 모의 테스트다. [테스트 환경과 재현 절차](../p2-p3-server.md#실행-환경)

범위의 근거는 중간고사 CallOps 기획서와 검토 피드백, 이후 확정한 웹 우선·선택 기능 포함 방향이다. 시제품의 차별화는 **거래처와 당시 합의한 내용을 찾아 답변의 근거 발화까지 확인하고, 이후 바뀐 현재 일정과 구분하는 과제**로 평가한다.
