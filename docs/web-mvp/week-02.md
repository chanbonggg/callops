# 2주차 · Whisper GPU 전사와 서버 수락

[이전 주](week-01.md) · [전체 계획](README.md) · [다음 주](week-03.md)

**종료 목표** · 업무로 지정한 가상 녹음 한 건을 실제 GPU에서 전사하고, 서버가 구간 ID·시간·텍스트를 검증해 수락한다. 평가 세트 20건·40문항을 확정한다.

GPU 데스크톱이 준비될 때까지 실제 전사·워커 시험은 대기한다. 현재는 [개발용 가상 전사](../../tests/fixtures/rag-development.json)로 서버 계약과 후속 웹 기능을 먼저 구현한다. 아래의 GPU 완료 항목은 실제 장비에서 검증한 뒤 체크한다.

## 작업

- [ ] [전사 실행 안내](../../ai-worker/README.md#전사-실행--wsl-데스크톱)의 기존 환경에서 새 `app.transcriber`를 실행한다. 모델·연산 설정, 음성 길이, 처리시간, 구간 범위와 주요 날짜·시각 오류를 기록한다.
- [ ] [형식별 검증표](week-01.md#형식별-검증표)에 따라 WAV·M4A·MP3·AMR 샘플을 공통 디코딩·전사 경로로 시험한다. 파일명과 내용이 다른 경우, 디코더가 거부하는 코덱, 재생용 파생 사본의 시간 구간과 삭제도 확인한다.
- [ ] 전사 결과에 작업·시도·입력 버전과 결과 스키마를 묶는다. 서버 수락 경로에서 구간 ID, 음성 범위 내 시작·끝, 빈 전사의 경고, 현재 임대·기한·입력 일치 여부를 검증한다.
- [x] 합성 결과로 작업·시도·입력 해시·버전을 검증하고 구간 전사를 저장·조회한다. 실제 모델 출력 수락은 별도 검증한다.
- [ ] 기존 큐 API에 실제 워커 한 개를 연결한다. 승인 작업 임대 → 입력 조회 및 해시 확인 → 실행 시작·heartbeat → 전사 → 결과 준비·업로드 → 서버 ACK → 로컬 사본 청소 순으로 시험한다.
- [ ] 전사 성공 결과는 서버에서 다시 조회할 수 있게 저장한다. 워커 오프라인, 연산 상한 초과, 만료 임대, 저장 직후 ACK 유실, 취소 후 정리를 재현한다. 가짜 워커 회귀도 실행한다.
- [ ] 최종 평가용 가상 전사 10건·질문 20개를 작성해 개발용과 구분한다. 최종용 질문·정답은 튜닝에 사용하지 않는다.

## 통과 기준

- GPU에서 얻은 전사 결과가 서버에 한 번 저장되고, 원음을 재생한 시각과 구간이 맞는다.
- 만료된 임대·변경된 입력·취소된 작업의 결과는 거절한다. ACK 유실 재요청 뒤 성공 결과와 다음 작업은 각각 하나다.
- 전사 오류·무음 경고·워커 미접속을 구분한다. 실제 GPU 연결 지연 시 정답 전사로 후속 RAG 개발을 진행하고 GPU 결과는 별도 미완료로 표시한다.
