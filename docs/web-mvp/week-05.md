# 5주차 · 고정 평가와 웹 업무 관리

[이전 주](week-04.md) · [전체 계획](README.md) · [다음 주](week-06.md)

**종료 목표** · 보류한 최종 질문 20개의 결과를 기록한다. 웹에서 일정·할 일을 관리하고, 모의 Calendar에서 승인·중복·장애 경계를 검증한다.

## 작업

- [ ] 모델·프롬프트·검색 설정을 고정한 뒤 최종 질문 20개를 평가한다. 각 질문의 정답 필드, 답변 또는 보류, 상위 5개 근거 ID, 오류 원인을 한 줄씩 기록한다.
- [ ] 일정·할 일 목록에 통화 후보에서 승인된 항목과 직접 입력한 항목을 함께 표시한다. 직접 입력·수정·삭제와 할 일 완료를 지원한다. 통화에서 나온 항목에는 원래 근거 링크를 남긴다.
- [ ] 일정의 승인 정보와 전송 상태를 분리하고, 내부 일정 ID와 Google 이벤트 ID의 연결을 정의한다. 하나의 시험 캘린더와 연결 일정의 생성·수정·삭제 경로를 기준으로 한다. 할 일은 CallOps에서 관리한다.
- [ ] 기존 승인·권한 경계와 연결되는 모의 어댑터로 승인·거절·전송 실패·재시도를 시험한다. 실제 OAuth와 시험 캘린더 사용 범위를 다음 주 실행 전에 확인한다.

## 평가 기준

| 지표 | 기록 방식과 목표 |
| --- | --- |
| 답변 정확성 | 핵심 정보와 근거가 맞는 정답 또는 적절한 보류. 초기 목표는 **17/20 이상**이며 최종 보고서에는 실제 수치를 적는다. |
| 검색 성공 | 필요한 근거가 상위 5개 안에 모두 들어온 답변 가능 문항 수를 기록한다. 여러 통화 문항은 필요한 근거를 모두 대조한다. |
| 근거·보류 경계 | 근거 ID 유효성 전수 확인. 권한 밖 근거 노출, 근거 부족 문항에서의 임의 확정, 삭제 기록 노출은 0건. |
| 추출과 전사 | 날짜·시각·요청 주체의 오류, 후보 누락·추가 수를 정답 전사 입력과 실제 STT 입력별로 기록한다. |

## 통과 기준

- 직접 등록한 할 일을 완료하고, 통화에서 온 일정은 근거를 다시 열 수 있다.
- 모의 Calendar에서 거절·미승인 일정의 등록은 0건이다. 생성은 성공했지만 응답을 받지 못한 경우, 기존 이벤트 조회와 재시도 후에도 일정은 1건이다.
- RAG 평가에서 목표에 못 미치면 원인을 기록하고 수정한 결과와 첫 고정 평가를 구분한다. 외부 연동 시험은 중복·권한 경계 검증을 통과한 뒤 시작한다.
