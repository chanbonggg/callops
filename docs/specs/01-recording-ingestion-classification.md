# SPEC-01 녹음 수집·임시 격리·수동 분류·삭제

| 항목 | 값 |
|---|---|
| 상태 | 검토 대기(Draft) |
| 작성일 | 2026-09-18 |
| 소유자 | 김찬영 |
| 구현 조건 | 본 문서 승인 후 구현 |
| 관련 후속 기능 | 작업 대기열, GPU 전사 워커, Ollama 추출, 승인 알림 |

## 결정 요약

1. 갤럭시 통화 녹음 원본은 갤럭시에 유지한다.
2. 홈서버는 새 녹음의 복사본을 임시 수신한다.
3. 사용자가 `업무 통화`를 선택하기 전에는 Whisper 전사와 Ollama 분석을 실행하지 않는다.
4. `사적 통화`를 선택하면 홈서버의 음성 복사본을 삭제한다.
5. 서버 측 삭제는 갤럭시 원본에 전파하지 않는다.
6. 업무 통화만 GPU 전달 대상으로 전환한다.
7. n8n은 CallOps 전용 인스턴스가 아니라 여러 자동화를 관리하는 홈서버 공용 인스턴스로 운영한다.
8. MVP에서는 디스크 암호화와 별도 백업을 적용하지 않는다. 이는 데이터 유출·유실 위험을 수용한 결정이며 실제 운영 전 재검토한다.

---

## 1. 기능명과 해결하려는 실제 업무 문제

### 기능명

갤럭시 통화 녹음의 단방향 수집, 임시 격리, 수동 업무 분류 및 서버 삭제

### 해결하려는 문제

통화에서 나온 일정과 후속 업무를 놓치지 않으려면 녹음을 자동 수집해야 하지만, 모든 통화를 자동으로 전사·요약하면 사적인 대화까지 AI가 처리한다. 연락처나 통화 시간만으로 업무·사적 통화를 정확히 구분할 수도 없다.

이 기능은 다음 두 요구를 동시에 해결한다.

- 새 통화를 놓치지 않고 홈서버에 수신한다.
- 사용자가 명시적으로 업무 통화라고 선택한 녹음만 AI 처리 대상으로 보낸다.

### 성공 기준

- 새 녹음을 홈서버에서 탐지하고 한 번만 등록한다.
- 분류 전에는 GPU 작업이 생성되지 않는다.
- 사적 통화의 서버 음성 파일이 삭제되고 갤럭시 원본은 유지된다.
- 업무 통화 선택은 해당 녹음 한 건에만 적용된다.
- 업무 통화 선택과 일정·할 일 등록 승인은 서로 독립적이다.

## 2. 사용자 시나리오 및 완료 조건

### 기본 시나리오

1. 갤럭시 기본 전화 앱이 통화 녹음을 생성한다.
2. 동기화 도구가 녹음 파일을 홈서버 수신 폴더로 전송한다.
3. 수집 서비스가 파일 전송 완료를 확인하고 SHA-256을 계산한다.
4. PostgreSQL에 수신 정보와 `분류 대기` 상태를 기록한다.
5. 공용 n8n이 최소 정보만 포함한 분류 요청 알림을 보낸다.
6. 사용자가 다음 중 하나를 선택한다.
   - `업무 통화`: GPU 처리 대기열 등록을 허용한다.
   - `사적 통화`: 홈서버 음성 복사본을 삭제한다.
   - `나중에 결정`: 처리하지 않고 재알림 시각만 예약한다.
7. 어떤 선택도 없으면 정해진 기한 후 서버 복사본을 삭제한다.

### 알림 예시

> 9월 18일 15:23 · 통화시간 8분 12초<br>
> 이 통화를 CallOps로 처리할까요?<br>
> `[업무 통화]` `[사적 통화]` `[나중에 결정]`

알림에는 전화번호, 연락처 이름, 파일명, 전사문, 통화 내용 및 계약 조건을 기본적으로 포함하지 않는다.

### 완료 조건

- `업무 통화` 선택 시 분류 상태가 `BUSINESS_APPROVED`가 되고 GPU 작업이 정확히 한 번 생성된다.
- `사적 통화` 선택 시 분류 상태가 `PRIVATE_EXCLUDED`가 되고 서버 파일 삭제가 완료된다.
- `나중에 결정` 선택 시 AI 처리는 시작되지 않고 지정 시각에 알림만 재시도된다.
- 중복 클릭과 동일 파일 재수신으로 중복 GPU 작업이 생기지 않는다.
- 홈서버 재시작 후에도 PostgreSQL 상태를 기준으로 이어서 처리한다.

## 3. 입력 데이터의 출처·형식·보관 위치

### 입력 출처

- 출처: 김찬영의 갤럭시 통화 녹음 폴더
- 생성 주체: 삼성 기본 전화 앱 또는 사용자가 확인한 통화 녹음 앱
- 실제 폴더 경로: 갤럭시 모델과 One UI 버전 확인 후 확정
- 전송 방식: Syncthing 또는 동일한 단방향 전송 보장을 제공하는 도구

### 허용 형식

초기 허용 목록은 다음과 같이 제안한다.

- `.m4a`
- `.amr`
- `.wav`

실제 갤럭시 녹음 확장자를 확인한 뒤 최소 허용 목록으로 줄인다. 확장자만 신뢰하지 않고 파일 헤더 또는 오디오 메타데이터 판독 결과도 확인한다.

### 분류 전에 읽을 수 있는 정보

- 파일 크기
- 수정 시각
- 오디오 길이
- 오디오 코덱 등 기술 메타데이터
- SHA-256 해시

분류 전에는 음성 인식, 내용 분석, 키워드 추출 및 요약을 금지한다.

### 홈서버 저장 위치

구현 시 실제 절대 경로를 확정한다. 논리 구조는 다음과 같다.

```text
callops-data/
├─ sync-inbox/       # 갤럭시에서 받은 수신 영역
├─ quarantine/       # 분류 전 접근 제한 영역
├─ gpu-outbox/       # 업무 승인된 녹음만 배치
└─ rejected/         # 자동 삭제 전 확인이 필요한 비정상 파일
```

`sync-inbox`와 `quarantine`은 GPU 데스크탑과 공유하지 않는다. n8n도 음성 파일을 직접 읽지 않고 DB 메타데이터만 사용한다.

### MVP 보관 정책 제안

| 대상 | 기본 정책 |
|---|---|
| 분류 대기 음성 | 수신 후 최대 72시간 |
| 사적 통화 음성 | 선택 즉시 삭제 요청 |
| 미응답 음성 | 72시간 만료 후 삭제 요청 |
| 업무 통화 음성 | 후속 보관·삭제 명세가 인계받음 |
| 사적/만료 파일의 SHA-256 tombstone | 90일 |
| 분류 결정 이력 | 90일 |
| 알림 시도 이력 | 30일 |

보관 기간은 본 문서 승인 과정에서 변경할 수 있다.

## 4. 입력 → 처리 → 저장 → 출력/알림 데이터 흐름

```text
[갤럭시 녹음 원본]
  │ 단방향 전송
  ▼
[홈서버 sync-inbox]
  │ 파일 안정화 검사
  │ SHA-256 및 오디오 메타데이터 확인
  ▼
[PostgreSQL 중복 검사]
  ├─ 기존 사적/만료 해시 → 서버 복사본 삭제
  ├─ 기존 처리 해시 → 중복 수신 기록 후 삭제
  └─ 신규 해시
       │
       ▼
[quarantine + 분류 대기]
       │
       ▼
[공용 n8n 분류 알림]
  ├─ 업무 통화 → GPU 작업 1건 생성 → gpu-outbox
  ├─ 사적 통화 → 모든 서버 음성 복사본 삭제
  └─ 나중에 결정/미응답 → 재알림 또는 만료 삭제
```

### 파일 안정화 조건

다음 조건을 모두 만족해야 수신 완료로 판단한다.

1. Syncthing 임시 파일이 아니다.
2. 두 번의 검사에서 파일 크기와 수정 시각이 동일하다.
3. 기본 검사 간격은 30초이다.
4. 파일을 읽을 수 있고 크기가 0보다 크다.
5. 허용된 오디오 형식으로 판독된다.
6. SHA-256 계산을 끝까지 완료한다.

### 원자적 격리 저장

1. `quarantine/.incoming/{uuid}.part`로 복사한다.
2. 복사본 해시가 수신 파일 해시와 같은지 확인한다.
3. 디스크 기록 완료 후 정식 저장 키로 원자적 이름 변경한다.
4. 파일 준비가 끝난 후 DB 상태를 `QUARANTINED`로 변경한다.

원본 파일명에는 연락처나 전화번호가 포함될 수 있으므로 격리 파일명은 UUID 기반 저장 키로 변경한다.

## 5. 사용하는 서비스와 각 서비스의 역할

| 서비스 | 역할 | 음성 내용 접근 |
|---|---|---|
| 갤럭시 녹음 앱 | 통화 녹음 원본 생성·보관 | 가능 |
| Syncthing 또는 동등 도구 | 갤럭시에서 홈서버로 파일 전송 | 파일 전송에 필요한 접근 |
| CallOps 수집 서비스 | 안정화 검사, 해시, 중복 검사, 격리·삭제 | 가능 |
| PostgreSQL | 메타데이터, 상태, 이력, tombstone 저장 | 원문 저장 금지 |
| 공용 n8n | 알림, 사용자 선택, 재시도 흐름 | 음성 파일 직접 접근 금지 |
| Uptime Kuma | 추후 서비스 상태 확인 | 접근 금지 |
| Whisper/Ollama | 본 기능의 업무 승인 이후 단계 | 분류 전 접근 금지 |

### 공용 n8n 운영 원칙

n8n은 홈서버의 여러 자동화를 위한 공용 인스턴스 하나를 사용한다. CallOps는 다음 논리 경계로 분리한다.

- CallOps 전용 n8n 프로젝트 또는 태그
- `CallOps / Ingest Classification`처럼 식별 가능한 워크플로우 이름
- CallOps 전용 DB 사용자 또는 제한된 API 자격증명
- CallOps 전용 알림 자격증명
- 워크플로우별 실행 데이터 보관·삭제 설정
- 다른 자동화 워크플로우가 CallOps 원본 파일에 접근하지 못하도록 파일 권한 분리

공용 n8n 장애가 다른 자동화에 영향을 줄 수 있으므로, CallOps 수집과 파일 보관은 n8n 없이도 안전하게 유지되어야 한다. n8n이 중단되어도 녹음은 `분류 대기`에 머물고 AI 처리는 시작되지 않는다.

## 6. 데이터 모델과 상태값

### recordings

녹음 콘텐츠 한 건을 나타낸다.

| 필드 | 설명 |
|---|---|
| `id` | UUID 기본키 |
| `sha256` | 콘텐츠 SHA-256, 고유 제약 |
| `size_bytes` | 파일 크기 |
| `extension` | 검증된 확장자 |
| `duration_seconds` | 메타데이터로 확인한 길이, 실패 시 NULL |
| `call_started_at` | 파일 메타데이터 기반 시각, 불확실하면 NULL |
| `storage_key` | UUID 기반 서버 저장 키 |
| `ingestion_status` | 수집 상태 |
| `classification_status` | 업무/사적 분류 상태 |
| `retention_deadline` | 미응답 자동 삭제 예정 시각 |
| `created_at`, `updated_at` | 생성·수정 시각 |
| `deleted_at` | 서버 음성 삭제 완료 시각 |

원본 파일명과 수신 경로는 민감 필드로 취급하며 필요한 기간에만 별도 제한 컬럼 또는 수신 이력에 저장한다. 일반 로그와 알림에는 노출하지 않는다.

### recording_receipts

같은 해시가 여러 번 도착하는 상황을 기록한다.

- 수신 UUID
- 녹음 ID
- 익명화된 장치 ID
- 민감 수신 경로
- 관찰된 크기와 수정 시각
- 최초·최종 관찰 시각
- 중복 여부
- 수신 결과

### classification_events

상태 변경 이력을 덮어쓰지 않고 누적한다.

- 녹음 ID
- 이전 상태와 새 상태
- 행위자: `USER`, `SYSTEM_EXPIRY`, `ADMIN_RECOVERY`
- 선택 채널
- 사유 코드
- 생성 시각

### notification_attempts

- 녹음 ID
- 알림 종류
- 시도 번호
- 성공/실패 상태
- 다음 재시도 시각
- 외부 메시지 ID(필요할 때만)
- 민감 내용이 제거된 오류 코드

### file_tombstones

삭제된 사적·만료 파일이 다시 동기화됐을 때 재알림과 재처리를 막는다.

- SHA-256
- 처분 상태: `PRIVATE_EXCLUDED`, `EXPIRED`, `DUPLICATE`
- 삭제 완료 시각
- 만료 시각

### 수집 상태

| 코드 | 사용자 표시 | 의미 |
|---|---|---|
| `DETECTED` | 파일 감지 | 새 파일 발견 |
| `STABILIZING` | 동기화 확인 중 | 전송 완료 대기 |
| `HASHING` | 중복 확인 중 | SHA-256 계산 중 |
| `QUARANTINED` | 분류 대기 | 격리 저장 완료 |
| `DUPLICATE` | 중복 파일 | 기존 해시 존재 |
| `REJECTED_UNSUPPORTED` | 지원하지 않는 파일 | 형식·크기 검증 실패 |
| `QUARANTINE_FAILED` | 격리 실패 | 복사·검증 실패 |
| `DELETE_REQUESTED` | 삭제 중 | 서버 파일 삭제 진행 |
| `DELETED` | 삭제 완료 | 서버 음성 복사본 없음 |

### 통화 분류 상태

| 코드 | 사용자 표시 | AI 처리 가능 여부 |
|---|---|---|
| `PENDING` | 분류 대기 | 금지 |
| `DEFERRED` | 나중에 결정 | 금지 |
| `BUSINESS_APPROVED` | 업무 처리 승인 | 허용 |
| `PRIVATE_EXCLUDED` | 사적 통화·처리 제외 | 금지 |
| `EXPIRED` | 미응답 만료 | 금지 |

일정·할 일 후보의 `확인 필요`, `승인 대기`, `승인됨`, `거절됨` 상태는 별도 기능에서 관리한다. `BUSINESS_APPROVED`는 통화의 AI 처리만 허용하며 외부 일정 등록을 허용하지 않는다.

## 7. 권한, 토큰, 개인정보 및 통화 녹음 보안 요구사항

### 파일 권한

- `sync-inbox`: 동기화 계정 쓰기, 수집 서비스 읽기
- `quarantine`: 수집 서비스만 읽기·쓰기
- `gpu-outbox`: 업무 승인 후 전달 서비스만 쓰기, GPU 동기화 계정 읽기
- n8n: 음성 폴더 접근 권한 없음
- 일반 사용자 및 다른 Docker 컨테이너: 접근 금지

구현 시 가능한 한 전용 Unix 사용자·그룹과 최소 권한을 적용한다.

### 네트워크

- Syncthing 장치는 명시적인 장치 ID로만 연결한다.
- 가능하면 VPN 고정 주소를 사용하고 글로벌 검색·릴레이 의존을 피한다.
- n8n 관리 화면과 승인 엔드포인트는 VPN 범위에서만 접근한다.
- PostgreSQL 포트는 Docker 내부 네트워크에만 둔다.
- Whisper, Ollama 및 GPU API는 인터넷에 공개하지 않는다.

### 비밀값

다음 값은 Git, n8n 실행 로그 및 오류 알림에 넣지 않는다.

- PostgreSQL 비밀번호
- `N8N_ENCRYPTION_KEY`
- Syncthing 장치 키와 GUI API 키
- 승인 API 토큰
- 알림 채널 토큰
- 향후 Google OAuth 토큰

비밀값 파일은 권한을 제한하고, `N8N_ENCRYPTION_KEY`처럼 손실 시 복구가 어려운 값은 비밀번호 관리자에 별도로 기록한다.

### 승인 링크

- 일회성 또는 짧은 만료 토큰 사용
- DB에는 토큰 원문이 아닌 해시 저장
- 이미 사용된 토큰 재사용 금지
- 녹음 ID만으로 상태 변경 금지
- 현재 상태를 조건으로 하는 원자적 업데이트 사용

### 로그 최소화

로그에 허용하는 정보:

- 작업·녹음 UUID
- 상태 코드
- 해시 앞부분 또는 내부 식별자
- 처리 시간
- 재시도 횟수
- 민감정보가 제거된 오류 코드

로그에 금지하는 정보:

- 전화번호와 연락처 이름
- 원본 파일명과 전체 경로
- 전사문과 통화 내용
- 전체 승인 토큰
- DB 연결 문자열

### MVP에서 수용한 위험

- 홈서버 루트 디스크는 암호화되지 않았다.
- 별도 물리 장치 백업이 없다.
- 서버 디스크 탈취·고장 시 데이터 유출 또는 유실 가능성이 있다.
- 갤럭시 원본으로 음성은 재처리할 수 있지만 DB 상태, 승인 이력 및 결과는 복구되지 않을 수 있다.

이 위험은 숨기지 않고 운영 문서에 표시하며, 실제 민감 통화 사용 범위가 커지면 LUKS 저장소와 별도 백업을 재검토한다.

### 통화 녹음 준수

CallOps는 녹음의 법적 허용 여부를 자동 판단하지 않는다. 사용자가 상대방 고지, 적용 법령 및 계약상 비밀유지 의무를 확인할 책임이 있다.

## 8. 실패 상황, 중복 실행, 재시도 및 복구 방식

| 실패 상황 | 처리 방식 |
|---|---|
| 파일 전송 중 감지 | 안정화 조건 충족 전까지 대기 |
| 동일 파일 재수신 | SHA-256 고유 제약으로 중복 처리 차단 |
| 사적/만료 파일 재등장 | tombstone 확인 후 알림 없이 서버 복사본 삭제 |
| 수신 파일 삭제 중 서버 재시작 | `DELETE_REQUESTED` 작업을 재개 |
| 격리 복사 중 중단 | `.part` 파일 정리 후 다시 복사 |
| DB 중단 | 파일을 삭제하지 않고 수신 영역에 유지, DB 복구 후 재시도 |
| 디스크 부족 | 신규 격리 중단, 최소 정보 관리자 알림, 기존 파일 임의 삭제 금지 |
| 형식 검증 실패 | `REJECTED_UNSUPPORTED`, 자동 AI 처리 금지 |
| 알림 실패 | 파일 처리 없이 알림 단계만 재시도 |
| 버튼 중복 클릭 | 최초 유효 결정만 반영하고 이후 요청은 기존 결과 반환 |
| 상충하는 버튼 클릭 | DB 조건부 업데이트에 먼저 성공한 결정만 유효 |
| n8n 중단 | `PENDING` 유지, AI 작업 생성 금지 |
| 휴대전화에서 먼저 삭제 | 서버에 완전한 격리본이 있으면 유지, 없으면 수신 실패 기록 |
| 서버 파일 삭제 실패 | `DELETE_REQUESTED` 유지 후 재시도, 원문 없는 오류 알림 |

### 기본 재시도 제안

- 격리 복사: 최대 3회, 1분/5분/30분
- 알림: 최대 5회, 지수 백오프
- 삭제: 1분/5분/30분 재시도 후 운영 경고, 이후 주기적으로 재시도
- DB 연결: 짧은 지수 백오프, 파일은 보존

### 멱등성 제약

- `recordings.sha256` 고유 제약
- GPU 작업의 `(recording_id, job_type)` 고유 제약
- 사용자 결정 요청의 `idempotency_key` 고유 제약
- 알림 전송 요청의 `notification_key` 고유 제약

### 상태와 파일 불일치 복구

수집 서비스 시작 시 다음을 조정한다.

- DB에 없지만 `.incoming`에 남은 파일 정리
- DB에는 존재하지만 격리 파일이 없는 작업을 `QUARANTINE_FAILED`로 표시
- `DELETE_REQUESTED`인데 파일이 남은 작업 재삭제
- `DELETED`인데 파일이 다시 생긴 경우 tombstone에 따라 삭제

## 9. 사람이 검토·승인해야 하는 지점

### 필수 승인 1: 통화 AI 처리 여부

사용자가 직접 `업무 통화`를 선택해야 Whisper/Ollama 처리가 가능하다. 기본값은 처리 금지다.

### 필수 승인 2: 추출 정보의 외부 반영

업무 통화를 승인했더라도 다음 항목은 별도 승인이 필요하다.

- Google Calendar 일정
- 할 일 시스템 등록
- 계약·가격·납기 관련 기록

AI는 일정 후보를 `승인됨`으로 변경할 수 없다.

### 결정 변경

- GPU 처리가 시작되기 전: 업무 승인을 취소하고 서버 음성을 삭제할 수 있다.
- GPU 처리 시작 후: 취소 요청을 기록하고 워커 중단 및 생성된 중간 결과 삭제 절차를 수행한다.
- 사적으로 제외한 통화: 서버 음성이 이미 삭제되었으므로 갤럭시 원본에서 다시 전송해야 한다.

## 10. 테스트 데이터와 검증 시나리오

실제 개인정보가 없는 인공 녹음만 사용한다.

### 기본 테스트 데이터

1. 명확한 업무 일정이 포함된 녹음
2. 모호한 일정 표현이 포함된 녹음
3. 일정이 없는 업무 대화
4. 사적인 대화
5. 낮은 음질의 대화
6. 이름만 다른 동일 음성 파일

### 수집·분류 검증

- 전송 중인 파일을 조기에 등록하지 않는다.
- 파일 안정화 후 SHA-256이 생성된다.
- 같은 파일을 두 번 넣어도 분류 알림과 GPU 작업이 중복되지 않는다.
- `업무 통화` 선택 전 Whisper/Ollama 호출이 0회다.
- `사적 통화` 선택 후 서버의 모든 음성 복사본이 사라진다.
- 서버 삭제 후 갤럭시 원본이 남는다.
- `나중에 결정` 후 AI 처리가 시작되지 않는다.
- 미응답 72시간 만료를 시간 가속 테스트로 검증한다.
- 같은 사적 파일이 재수신되면 알림 없이 삭제된다.
- 지원하지 않는 파일은 AI 처리되지 않는다.

### 장애 검증

- 수집 중 서버 재시작
- PostgreSQL 중단과 복구
- n8n 중단과 복구
- 디스크 부족 모의 상황
- 격리 복사 실패
- 알림 전송 실패
- 삭제 권한 오류
- 승인 버튼 빠른 중복 클릭
- `업무 통화`와 `사적 통화` 동시 요청

### 보안 검증

- n8n 컨테이너가 음성 폴더를 읽을 수 없어야 한다.
- PostgreSQL이 호스트·인터넷 포트에 공개되지 않아야 한다.
- 로그에서 전화번호, 연락처, 파일명, 토큰 및 원문을 검색해 발견되지 않아야 한다.
- Git 추적 파일에 `.env`, 녹음, DB 덤프가 없어야 한다.

## 11. 운영 로그, 지표, 알림 및 복구 확인 항목

### 운영 지표

- 신규 수신 수
- 상태별 녹음 수
- 가장 오래된 `PENDING` 시간
- 업무/사적/나중에 결정 비율
- 중복 파일 차단 수
- 알림 성공·실패·재시도 수
- 삭제 요청 및 삭제 실패 수
- `sync-inbox`, `quarantine`, `gpu-outbox` 사용량
- 수집 서비스와 n8n의 마지막 정상 응답 시각

### 운영 알림

- 디스크 잔여 공간 부족
- DB 연결 실패 지속
- 격리 복사 3회 실패
- 파일 삭제 반복 실패
- 24시간 이상 분류 대기 급증
- n8n 또는 수집 서비스 중단

### 로그 형식

구조화 로그에 `event`, `recording_id`, `status`, `attempt`, `duration_ms`, `error_code`만 기록한다. 민감정보는 로그 생성 전에 제거한다.

### 복구

- 구성과 DB 마이그레이션은 private Git 저장소로 복원한다.
- 비밀값은 Git 외부에서 다시 주입한다.
- 음성은 갤럭시 원본이 남아 있을 때 다시 수신할 수 있다.
- 백업이 없으므로 PostgreSQL 상태, 승인 이력 및 결과는 완전 복구를 보장하지 않는다.
- Uptime Kuma는 추후 공용 상태 점검 도구로 재사용한다.
